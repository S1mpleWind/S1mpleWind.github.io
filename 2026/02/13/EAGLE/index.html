Extrapolation Algorithm for Greater Language-model Efficiency , EAGLE 算法学习

前面看完了Medusa方法，再看加速效果更好的EAGLE

EAGLE

下图是这几种方法的对比：

  • spec sampling 是 token-level
  • Medusa 是利用一个 feature 用不同的 head 去预测不同位置的 token
  • EAGLE 是将 token 和 feature 混合输入

论文首先指出这个方法的提出和实现基于两个观察：

  • feature-level 的自回归比 token-level 要容易，因为token的采样是随机的
  • sampling 过程中产生的随机性会显著限制预测 next feature 的表现，而在输入中加入上次采样得到的 token ，能有效消除这种不确定性

提炼

看完整篇论文，我认为相较于 Medusa 利用多头去处理 feature ，EAGLE则是训练了一个针对 feature 的 draft model 。

针对上面的观察一，我的理解是：一个标准的 llm 输入输出都是 token ，而 token 采样的时候引入了不确定性，这会要求模型有更多的参数和计算来提升精度，因此很难获取一个非常理想的 token-level 的 draft model 。并且由于 token-level 的问题是离散空间里稀疏变量的问题，而 feature 则是一个高维的连续向量。因此 feature 的变化是容易学习的，针对他设计的模型也更简单，推理也快得多

而针对上面的观察二，我的理解是：在常规llm流程中，一般是 hidden_states -> logits -> 采样得到token -> hidden_state，也就是说采样这一步给feature引入了不确定性。为了消除这个不确定性，可以把采样完的 token 和 hidden_state(feature) 一并输入；换句话说，从 fif_ifi​ 出发，当前的 feature 并不知道自己要往哪个方向进行变化，因为是 token 的采样决定了它这一轮的变化，所以将采样完的 token 一并作为数据，相当于告诉了 fif_ifi​ 一个走向 fi+1f_{i+1}fi+1​的方向，可以极大消除的不确定性，提高接受率。

论文节选

1. EAGLE pipeline / Draft Model

下图为 EAGLE 推理的流程：

  • green : embedding
  • orange : feature
  • red : prediction of draft model
  • blue (with snow icon) : target LLM parameter

可以看到这里 Draft Model 由三部分组成：

  1. Embedding Layer : 与目标 LLM 共享
  2. LM Head : 与目标 LLM 共享
  3. Autoregression Head ：由一层 FC layer 和一层 decoder 构成

Draft Model 的输入是一个形状为 (bs, seq_len, hidden_size) 的 feature 和一个形状为 (bs, seq_len) 的 token 。token 序列会被 embedding层转换成 embedding ，最后合并成形状为 (bs, seq_len, 2*hidden_size) 的输入

FC 层的作用是将 (bs, seq_len, 2*hidden_size) 降维成 (bs, seq_len, hidden_size)

在计算 draft 的时候，EAGLE 构建了一颗树。这棵 Draft Tree 的深度是mmm ，拥有超过mmm个的 token 数，只会执行mmm步 forward。

例如，下图是草稿生成的过程中构建的树，可以看到天然的不含有 Medusa 中那种缺乏逻辑性的分支。 这里深度为3，token数为10

对于这颗树的构建规则，附录中有提到一些：

  • greedy：每个节点选择 top k 作为儿子
  • intuition：高概率的分支应该更深/更广

最终都使用了这颗静态的树

2.Training

这是草稿模型进行一次前向传播f^i+1=DraftModel([fi;e(ti)])\hat{f}_{i+1} = DraftModel([f_i; e(t_i)])f^​i+1​=DraftModel([fi​;e(ti​)])

预测下一个 feature 使用了残差的方式，并使用了 Smooth L1 作为损失

Lreg=Smooth L1(fi+1,Draft_Model(T2:i+1,F1:i))L_{reg} = Smooth \space L1 (f_{i+1} , Draft\_Model(T_{2:i+1}, F_{1:i})) Lreg​=Smooth L1(fi+1​,Draft_Model(T2:i+1​,F1:i​))

而预测下一个 token 则是一个 Classification loss

pi+2=Softmax(LMHead(fi+1))p_{i+2} = Softmax(LM Head(f_{i+1})) pi+2​=Softmax(LMHead(fi+1​))

p^∗i+2=Softmax(LMHead(f^∗i+1))\hat{p}*{i+2} = Softmax(LM Head(\hat{f}*{i+1})) p^​∗i+2=Softmax(LMHead(f^​∗i+1))

Lcls=CrossEntropy(pi+2,p^i+2)L_{cls} = CrossEntropy(p_{i+2}, \hat{p}_{i+2}) Lcls​=CrossEntropy(pi+2​,p^​i+2​)

最后联合回归损失和分类损失，得到L=Lreg+wcls∗LclsL = L_{reg} + w_{cls}*L_{cls}L=Lreg​+wcls​∗Lcls​

通常分类损失是显著大的，所以论文中将权重www设置为了 0.1

3.Verify

使用了和 Medusa中类似的 Tree Attention

EAGLE-2

和第一版的主要区别是树的变化 （Context-aware dynamic draft tree）

文章在开头首先指出了 EAGLE 和 Medusa 使用的都是同样的静态 draft tree ，这本质上基于了一个假设：一个 token 的接受率很大程度上取决于他在这个树上的位置

但是这和 spec sampling 中 *“some tokens are simpler and can be predicted by smaller models”*会产生冲突，实验也发现了 token 接受率还和上下文密切相关。因此静态树有天然的限制。在不同的 context 下动态的调整树会更好

要想拥有更适应 context 的动态结构，就需要原始 LLM 对上下文的推导。但是这与加速的目的相悖了。但是 EAGLE 的实验结果证明了 draft model 具有良好的校准性（Well-calibrated），它的置信度分数（即概率）能够很好地近似 Draft Token 的接受率

EAGLE-2 基于这一点事实展开，通过动态树的构建提高了接受率（acceptance rate）

Well-Calibrated Draft Model

EAGLE-2 提供了这样一张统计图，其中Confidence(x)=Pdraft(x)=exp⁡(Logitx)∑exp⁡(Logiti)Confidence(x) = P_{draft}(x) = \frac{\exp(Logit_x)}{\sum \exp(Logit_i)}Confidence(x)=Pdraft​(x)=∑exp(Logiti​)exp(Logitx​)​，Acceptance Rate=min⁡(1,Ptarget(x)Pdraft(x))\text{Acceptance Rate} = \min\left(1, \frac{P_{target}(x)}{P_{draft}(x)}\right)Acceptance Rate=min(1,Pdraft​(x)Ptarget​(x)​)

Confidence 就是 Draft 预测的分布；而接受率在贪婪搜索下就是 PtargetP_{target}Ptarget​和 PdraftP_{draft}Pdraft​预测的最可能的结果一致，在随机采样中是如果 target 认为这个词出现的概率比 Draft 预测的概率还大，那么就是 1.0 的接受率，否则按照比例接受

这样的校准性能够避免使用 Target LLM 对上下文的推导，仅仅用 Draft 就能寻找动态树的路径

Expansion of tree

Tree Attention 可以很好的并行验证，但是token太多开销过大，因此需要选择性的添加token

因为否定一个 token 就是截断这条路径，所以衡量一个 token 的价值的值是 Global Acceptance，即Vi=∏ij∈Path(root,ti)pj≈∏ij∈Path(root,ti)cjV_i = \prod_{i_j \in Path(root,t_i)} p_j \approx \prod_{i_j \in Path(root,t_i)} c_jVi​=∏ij​∈Path(root,ti​)​pj​≈∏ij​∈Path(root,ti​)​cj​，然后留下 top-k的 token

Reranking Nodes

经过 expand 之后，还要进行一次排序筛选，保留所有节点中期望收益最高，也就是 Global Acceptance最大的 mmm 个 token

这一步会有一个现象，就是浅层的 token 会比深层的 token 更有优势，因为每一次都是乘一个小于 1 的数，所以当模型很自信的时候，会生成更深的路径，一次推理中能走更多的步骤；而当模型很困惑的时候，树的结构趋向于“收缩”，预测趋于浅层，节省深层 token 验证的资源，提高整体期望值

EAGLE-3

第三版主要是在训练上

新的训练架构

Training-time test

EAGLE 的训练是基于 feature-level 的，训练的损失是联合回归损失和分类损失L=Lreg+wcls∗LclsL = L_{reg} + w_{cls}*L_{cls}L=Lreg​+wcls​∗Lcls​。LregL_{reg}Lreg​是feature的损失，但是LclsL_{cls}Lcls​的 token 损失其实才是最终的目标。这也就意味着 feature 会施加一个额外的约束，让 Draft Model 很难在更大的 training data 中获益。为此 EAGLE-3 做了这样的尝试：

  1. 取消 feature 的 loss ：0-α0\text{-}\alpha0-α显著提高，但是feature的预测显著下降导致1-α1\text{-}\alpha1-α以及后续急剧下降
  2. 当前的训练是割裂的训练每一步，最终得到是一个单步预测器，因此幻觉可能在推理的过程中积累。通过在训练中加入推理得到的数据，可以很好的解决；同时可以把 feature 以这种形式加入训练

上图展示了两种方法的逻辑，这种新的方法被命名为 training-time test

特征利用

过去只使用最后的一层 hidden_layer 这个 feature ， 但是现在充分利用了其他的更多的 feature

Scaling Law

新的架构随着 Data 的增长，Accept Rate 也显示出了增长

Pipeline

第三版的pipeline如下图。除了增加了底层的 hidden_state 的使用；同时由于训练的时候使用的新方法，draft 部分原本的单步预测器也变成了更 transformer 的 decoder；decoder输入的序列中，会重复使用生成的 draft feature，对应了训练得到的”轨迹感“，能根据前面所有步骤形成的动态趋势进行自我修正

Training

唯一要训练的部分就是 transformer decoder，训练的时候用了 tree-mask，从一个序列里产出的只能看到它这条路径上的Key（示意图里用 token 来代替了 feature 的表示）

对于每一步的训练，由于浅层的错误是更致命的，所以可能会给不同深度的节点分配训练权重，看代码的时候看看

总结

EAGLE 由于加入了 token 的选择，可以加强 spec 过程中的上下文逻辑，减轻不确定性，从而获得更高的 Accept Rate

第二版通过动态树的结构，算是优化了算力的调度，让计算资源流向了更有用的 token ，提升了推理效率

第三版主要是在训练上增强，提升了 Draft Model 的表现
